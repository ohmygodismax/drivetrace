# DriveTrace

Нативный Android-прототип автомобильной телеметрии: Kotlin, Jetpack Compose, Room, DataStore и MapLibre Native. Тёмный интерфейс с IBM Plex Sans и IBM Plex Mono. Профиль демонстрационного автомобиля — Volkswagen Tayron 1.4 TSI, 2023.

## Запуск

Откройте проект в Android Studio и запустите `app` на устройстве/эмуляторе Android 8.0+ (API 26). Для сборки нужны JDK 17+ и Android SDK 36.

```sh
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest :app:lintDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

## Подключение

Стартовый экран содержит только поиск автомобиля и кнопку настроек подключения. Симуляция по умолчанию выключена. Реальная интеграция Bluetooth / ELM327 пока не реализована: поиск в обычном режиме сообщает об этом, не выдавая виртуальный адаптер за реальный.

Чтобы проверить прототип без автомобиля:

1. Откройте настройки подключения справа вверху.
2. Включите «Режим симуляции» и нажмите «Готово».
3. Нажмите «Найти автомобиль», подключите найденный виртуальный ELM327 и откройте приборы.
4. В блоке «Симулятор» выберите сценарий: город, трасса, динамичный или неисправность. Доступны пауза, сброс и скорость 1× / 2× / 5×.
5. Начните и завершите запись закреплённой кнопкой. Смена сценария и сброс на время записи заблокированы.
6. Откройте запись в «Поездках». Карта, показатели, график и события используют общую шкалу времени. Можно перематывать, менять скорость и переходить к событиям.
7. Экспорт CSV доступен по кнопке скачивания в плеере. Используется системный диалог сохранения. В CSV есть UTC, единицы, признак симуляции и расчётная нагрузка; скорость и расстояние экспортируются в км/ч и км независимо от единиц интерфейса.

Настройки единиц, интервала и режима симуляции сохраняются. Отключение возвращает к поиску. Удаление поездки требует подтверждения.

## Карта и дорожный маршрут

Используется настоящая векторная карта MapLibre Native, тёмный стиль OpenFreeMap, данные OpenStreetMap. Для подложки нужен интернет; ключи API не нужны. Доступны перемещение, масштабирование, кнопка показа всего трека и атрибуция поставщиков.

Симулятор движется по заранее подготовленному замкнутому дорожному маршруту Москвы длиной около 11 км. Геометрия получена из OpenStreetMap через OSRM и встроена в приложение; запросов к сервису маршрутизации при использовании нет. Положение определяется пройденной дистанцией, а не независимым изменением широты/долготы.

Запись сохраняет абсолютное смещение на дорожном маршруте. При отрисовке между кадрами добавляются все промежуточные вершины дороги: редкие замеры и ускорение 5× не превращают повороты в прямые через кварталы. Маркер использует сохранённые координаты. Пройденная часть яркая, оставшаяся приглушена.

Цвет участка определяется максимальной расчётной нагрузкой двух ограничивающих его кадров:

- синий — обычная, менее 45%;
- янтарный — повышенная, 45–69%;
- красный — высокая, от 70%;
- серый — данных недостаточно.

Это демонстрационная оценка `0.8 × throttlePct + 20 × rpm / 4500`, ограниченная диапазоном 0–100%, а не измеренный PID нагрузки двигателя. При отсутствии оборотов или дросселя значение отсутствует. Сценарий «Динамичный» содержит выраженные участки высокой нагрузки. Дроссель учитывает ускорение и скорость; при высокой нагрузке создаётся событие на таймлайне.

Для тестовых неисправностей выберите соответствующий сценарий и 5×: после 30 секунд падает напряжение, после 43 секунд появляется перегрев, на 45–51 секунде пропадают поля телеметрии, на 60-й секунде возникает тестовый DTC.

## Структура

- `Telemetry.kt` — кадры, источник, детерминированный симулятор (`seed = 42`), CSV.
- `DemoRoute.kt` — дорожная геометрия, интерполяция и сохранение поворотов между замерами.
- `RoadTrack.kt` — расчётная нагрузка, классификация и дорожные сегменты.
- `RouteMap.kt` — нативная карта, цветные сегменты, маркер, жизненный цикл и обработка ошибок загрузки.
- `Store.kt` — Room, пакетная запись, события и DataStore.
- `Design.kt` — встроенные шрифты и типографика.
- `MainActivity.kt` — подключение, приборы, история, плеер и настройки.

Один движок принадлежит Application: пересоздание Activity не создаёт второй генератор. Интервалы измеряются монотонными часами, в записи сохраняется смещение от начала. Измерения пишутся пакетами по восемь кадров. Незавершённые поездки получают статус «Прервана» после следующего запуска; итоги восстанавливаются из сохранённых кадров. При аварийной остановке могут потеряться последние семь кадров буфера. Room v2 добавляет смещение маршрута через совместимую миграцию.

Поездки остаются в локальной базе, но поставщик карты получает запросы картографических плиток для выбранной области. Записи и CSV на сервер не загружаются.

## Границы прототипа

Реальные Bluetooth, ELM327, GPS, Android Auto, управление ЭБУ и Foreground Service отсутствуют. Все показания синтетические. Надёжная фоновая запись требует следующего этапа реализации. Это прототип телеметрии, не аварийный регистратор.
