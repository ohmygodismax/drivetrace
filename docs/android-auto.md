# Android Auto: прототип для Desktop Head Unit

Интеграция доступна только в `debug`: сервис, ресурсы и зависимости Car App Library не входят в `release`.

На экране — скорость, обороты, температура охлаждающей жидкости, напряжение и состояние записи. Скорость учитывает настройку км/ч или миль/ч на телефоне. Отсутствующие показатели отображаются как «—», симуляция явно подписана. Экран запрашивает обновления раз в секунду, пока открыт; фактическую частоту определяет Android Auto.

Кнопки «Начать запись» и «Сохранить поездку» используют тот же движок и базу, что телефон и уведомление. Сохранение завершает поездку, не отключая адаптер. Закрытие экрана Android Auto не завершает запись. Сопряжение ELM327, разрешения и выбор симулятора выполняются на телефоне. Без подключения показывается инструкция, кнопки записи нет. Автоматического подключения и старта записи нет.

## Ограничение категории

В debug-манифесте категория `POI` используется только как техническое объявление для обнаружения прототипа в DHU. DriveTrace не реализует поиск мест и не соответствует этой категории для публикации. В debug разрешены тестовые хосты через `ALLOW_ALL_HOSTS_VALIDATOR`; весь сервис исключён из release. Для публикации категория и проверка хостов требуют отдельного решения.

## Подготовка

1. На Android-телефоне или Android-эмуляторе с Google Play установите/обновите полноценную Android Auto через Google Play. Системная версия с суффиксом `-stub` не подходит. Для обновления в эмуляторе потребуется вход в Google Play.
2. Установите **Android Auto Desktop Head Unit Emulator** через Android Studio → SDK Manager → SDK Tools. Либо выполните:

   ```sh
   "$ANDROID_HOME/cmdline-tools/latest/bin/sdkmanager" 'extras;google;auto'
   ```

3. На Linux для DHU нужны `libc++.so.1` и `libc++abi.so.1` (пакеты `libc++1`, `libc++abi1` в Ubuntu). Если они установлены отдельно в пользовательский каталог, добавьте его в `LD_LIBRARY_PATH` при запуске DHU.
4. В настройках Android Auto нажмите на сведения о версии 10 раз и включите режим разработчика. В меню разработчика выберите **Start head unit server / Запустить сервер головного устройства**.

## Сборка и запуск

`ANDROID_HOME` — каталог Android SDK; на текущем компьютере это `/home/mkulakov/Android/Sdk`. Если подключено несколько устройств, используйте `adb -s SERIAL`, а для Gradle задайте `ANDROID_SERIAL=SERIAL`.

```sh
./gradlew :app:installDebug
adb forward tcp:5277 tcp:5277
"$ANDROID_HOME/extras/google/auto/desktop-head-unit" --adb=127.0.0.1:5277
```

В DriveTrace на телефоне включите симуляцию в настройках подключения, выберите виртуальный автомобиль и подключитесь. В меню приложений DHU откройте DriveTrace.

На текущем компьютере DHU уже установлен, а недостающие Linux-библиотеки распакованы в пользовательский каталог без изменения системных пакетов. После обновления Android Auto и запуска сервера головного устройства используйте:

```sh
./gradlew :app:installDebug
adb forward tcp:5277 tcp:5277
LD_LIBRARY_PATH="$HOME/.local/share/drivetrace/dhu-libs/usr/lib/x86_64-linux-gnu${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}" \
  /home/mkulakov/Android/Sdk/extras/google/auto/desktop-head-unit --adb=127.0.0.1:5277
```

Если приложение не появилось: убедитесь, что установлена debug-сборка, перезапустите соединение DHU и проверьте обновление Android Auto. Опция «Неизвестные источники» сама по себе не снимает ограничения Car App Library. Для тестов в настоящем автомобиле официальный путь — установка через Internal App Sharing или внутренний трек Google Play.

## Ручная проверка в DHU

1. Без подключения на телефоне: видна инструкция, кнопок записи нет.
2. Подключить симулятор: показатели меняются, есть подпись «Симуляция».
3. Нажать «Начать запись»: статус меняется, появляется время записи и кнопка сохранения. На телефоне также отображается запись.
4. Дважды нажать начало: повторное нажатие не должно завершить поездку.
5. Нажать «Сохранить поездку»: поездка появляется в истории телефона, показатели продолжают обновляться.
6. Начать следующую запись, закрыть экран DHU, открыть снова: запись продолжается.
7. Начать/завершить запись с телефона: экран DHU отражает новое состояние.
8. Отключить автомобиль на телефоне: экран DHU возвращается к инструкции, поездка сохраняется существующим движком.
9. Повторить с реальным ELM327 позже: отдельно проверить одновременную работу Android Auto и Bluetooth Classic.

## Автоматические проверки

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
./gradlew :app:connectedDebugAndroidTest \
  -Pandroid.testInstrumentationRunnerArguments.class=dev.drivetrace.car.CarTelemetryTest
```

`CarTelemetryTest` запускается на Android-устройстве/эмуляторе с тестовым хостом Car App Library, настоящими движком и Room. Проверяет экран без подключения, симуляцию, начало/сохранение, сохранённые кадры, повторные нажатия и продолжение записи после уничтожения автомобильного экрана. Эти проверки не заменяют визуальную проверку в DHU.

Документация: [DHU](https://developer.android.com/training/cars/testing/dhu), [тестирование и ограничения установки](https://developer.android.com/training/cars/testing), [Car App Library](https://developer.android.com/training/cars/apps/library).
