# DriveTrace — техническое задание и план MVP

> **Цель:** Android-приложение «чёрный ящик автомобиля»: собирает телеметрию, записывает поездки и воспроизводит историю с графиками и маршрутом. Первую версию разрабатываем **без автомобиля**, на встроенном симуляторе. Позже подключаем ELM327 и при необходимости изучаем вывод ограниченной информации в Android Auto.

## 1. Область проекта

**Название (рабочее):** DriveTrace. Не привязано к Volkswagen или конкретной модели; перед публичным релизом проверить название и товарные знаки.

**Устройства:** Android-телефон. **Первая версия работает полностью локально**, без учётных записей и сервера.

**Режимы:**
- **Live** — отображение текущей телеметрии и старт/стоп записи.
- **Trips** — история записанных поездок.
- **Replay** — синхронное воспроизведение параметров и маршрута.
- **Settings** — выбор источника (Simulator сейчас; ELM327 позже), единицы измерения, настройки записи.

**Ограничения MVP:** данные полностью синтетические; они не должны подаваться как реальные показания автомобиля. Не реализуем управление блоками автомобиля, запись команд в ЭБУ или изменение функций безопасности. Android Auto не входит в MVP: произвольные диагностические интерфейсы ограничены политикой и шаблонами AA.

## 2. Технологии

| Уровень | Стек | Назначение |
|---|---|---|
| Платформа | Kotlin, Android SDK | Android-приложение |
| UI | Jetpack Compose, Material 3 | Экран приборов, история и плеер |
| Асинхронность | Kotlin Coroutines, StateFlow/Flow | Поток измерений |
| Хранилище | Room (SQLite) | Поездки, измерения, события |
| Настройки | DataStore | Источник данных, частота симуляции, единицы |
| GPS в будущем | Fused Location Provider | Реальная геопозиция с разрешением пользователя |
| Датчики в будущем | SensorManager | Ускорение, ориентация телефона |
| ELM327 в будущем | Android Bluetooth Classic / BLE | Транспорт в зависимости от адаптера |
| Карта | MapLibre (или начать с упрощённой схемы маршрута) | Replay без обязательного облака |
| Графики | Compose Canvas или Android-совместимая библиотека | Графики RPM, скорости и температур |
| Экспорт | Storage Access Framework + CSV | Выгрузка поездок |

**Примечание:** отдельный React + TypeScript веб-плеер — необязательное расширение после Android MVP, не блокирует первую версию.

## 4. Модель данных

Используем временные метки **UTC epoch milliseconds** для долговременного хранения и **монотонное время** для измерения интервалов в рамках работающего приложения (защита от изменения системных часов). Каждый кадр имеет `source` и `simulated`.

```kotlin
enum class TelemetryOrigin { SIMULATOR, ELM327 }

data class TelemetryFrame(
    val timestampMs: Long,
    val elapsedRealtimeMs: Long,
    val origin: TelemetryOrigin,
    val simulated: Boolean,
    val rpm: Int?,
    val speedKmh: Double?,
    val coolantC: Double?,
    val intakeC: Double?,
    val voltageV: Double?,
    val throttlePct: Double?,
    val latitude: Double?,
    val longitude: Double?
)

interface TelemetrySource {
    val frames: kotlinx.coroutines.flow.Flow<TelemetryFrame>
    suspend fun connect()
    suspend fun disconnect()
}
```

`null` означает «показатель недоступен», а не ноль. В БД отдельно храним:
- `Trip`: идентификатор, начало/конец UTC, сценарий/источник, статус и итоговые метрики.
- `TelemetrySample`: `tripId`, timestamp, монотонное смещение, измерения, координаты и признак симуляции.
- `TripEvent`: `tripId`, timestamp, тип (`HARD_BRAKE`, `OVERHEAT`, `CONNECTION_LOSS`, `DTC_SIMULATED`), подробности.

Для воспроизведения сортируем по монотонному смещению от начала поездки; графики, карта и маркеры используют **одну позицию таймлайна**. При поступлении данных в разное время (реальный ELM327/GPS) не подразумеваем их физическую одновременность.

## 5. Встроенный симулятор

Генерация кадра каждые **200–500 мс** для начала (настраиваемо). Использовать детерминированное случайное зерно (`seed`), чтобы тестовые поездки можно было воспроизвести точно. Не генерировать каждый показатель независимо: RPM, скорость, дроссель и нагрузка должны быть согласованы с фазой движения.

### Сценарии

| Сценарий | Поведение | События |
|---|---|---|
| City Drive | Холостой ход, светофоры, разгоны до ~60 км/ч | Остановки, эпизод торможения |
| Highway | Разгон до ~90–120 км/ч, стабилизация | Манёвр, изменение нагрузки |
| Aggressive Drive | Чередование ускорений и замедлений | Резкий разгон и торможение |
| Fault Scenario | Поездка с отклонениями показателей | Рост температуры, просадка напряжения, обрыв потока, тестовый DTC |

**Типовые синтетические диапазоны** (не спецификация Tayron):
- RPM: ~750–4500 об/мин.
- Скорость: 0–130 км/ч.
- Охлаждающая жидкость: прогрев от окружающей температуры до ~90 °C; неисправность может выходить за нормальный сценарий.
- Напряжение: ~13,7–14,4 В при работающем двигателе как демонстрационный сценарий.
- Дроссель: 0–100%; координаты задаются по заранее подготовленному маршруту или упрощённой траектории.

Добавить кнопки симулятора **Start / Pause / Reset / Scenario** и переключатель скорости воспроизведения (`1×`, `2×`, `5×`), если не усложнит первую итерацию.

## 7. Позднее: реальный ELM327

Добавить `Elm327TelemetrySource`, реализующий тот же интерфейс. Сначала определить тип адаптера: **Bluetooth Classic, BLE или Wi-Fi** (это разные механизмы подключения). Не предполагать, что любой ELM327 поддерживает все варианты.

Пример команд для стандартного OBD-II:

```text
ATZ    # reset
ATE0   # echo off
ATL0   # linefeeds off
ATSP0  # auto vehicle protocol
010C   # RPM
010D   # vehicle speed
0105   # coolant temperature
0111   # throttle position
010F   # intake air temperature
0142   # ECU control module voltage (if supported)
```

Парсить ответы с учётом `>`, эха, пробелов, таймаутов, `NO DATA`, `SEARCHING...`, нескольких ECU и отрицательных ответов. Например `41 0C 1A F8` означает `(0x1A * 256 + 0xF8) / 4 = 1726 RPM`.

**Важно:** стандартные PID поддерживаются не всеми ЭБУ; расширенные Volkswagen PID требуют отдельной проверки. Реальные GPS и OBD измеряются с разными частотами. Для Android-фоновой записи нужны соответствующие разрешения, уведомление Foreground Service и тестирование ограничений энергосбережения. Не рассчитывать на высокую частоту опроса дешёвого ELM327.

## 8. Позднее: Android Auto

Построить независимый модуль отображения, использующий данные репозитория. **Не обещать произвольную панель приборов через официальный Android Auto SDK:** Android Auto ограничивает допустимые категории и шаблоны приложений. Неформальные способы могут ломаться после обновлений и требуют отдельного тестирования. Запись на телефоне должна полностью работать без Android Auto.

## 9. Идеи после MVP

- Кольцевой буфер последних **5 минут до события + 2 минут после** (настраиваемо).
- Автоматические метки: резкое торможение, необычный прогрев, DTC, потеря соединения.
- Видео с камеры телефона при явном согласии пользователя и с учётом ограничений фоновой съёмки.
- Защита/шифрование экспорта, удаление поездок и контроль приватности GPS-треков.
- Веб-плеер на React + TypeScript для просмотра экспортированных поездок.
- Автоматический старт поездки по подключению к адаптеру — только после проверки фоновой работы.

**Оговорка:** DriveTrace — инструмент телеметрии, не сертифицированный аварийный регистратор; данные ELM327, GPS и датчиков телефона нельзя считать точным доказательством обстоятельств ДТП.

1. Создать пустой проект Compose.
2. Добавить `TelemetryFrame`, `TelemetrySource`, `SimulatorTelemetrySource`.
3. Собрать Live Screen с шестью показателями и пометкой **SIMULATED**.
4. Сделать стабильный сценарий City Drive с `seed = 42` и обновлением каждые 250 мс.
